The waitlist feature

Let a patient join a waitlist for an already-booked slot; when that booking is cancelled, auto-promote the first in line (FIFO) and keep the slot booked. Synthetic only (PT-0007), no PHI.

Four high-level steps — one per subagent:
  1. Model — add a waitlist table (db.js)
  2. Routes — join / list / leave endpoints (waitlist.js)
  3. Promotion — auto-promote FIFO on cancel (bookings.js)
  4. Tests — un-skip the spec, get to green

The bad prompt (drift, then recover)

Add the waitlist feature. Do whatever
you think is best, and while you're in

Don't bother showing me a plan.

Vague + invites scope creep + skips the plan → it over-reaches. Then: Esc, /rewind to the good checkpoint, /clear, and restart with this:

THE GOOD PROMPT (RECOVERY)
Add only the waitlist feature from
docs/waitlist-task.md. Work plan-first:

touch unrelated code. After I approve:
implement it, un-skip tests/waitlist.test.js,
and run the suite until it's green.

Scoped + plan-first + a clear verification gate (green tests). Same task, opposite behavior. That contrast is the lesson.
